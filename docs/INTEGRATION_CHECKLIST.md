# 接入信息清单

为了把示例适配成可实际运行的内网工程，请提供以下信息。密钥不要发到聊天或提交 Git；只需说明它应从哪个环境变量/密钥系统读取。

## 必需

1. **执行拓扑**：本项目最终运行在本机、跳板机，还是内网训练机？哪台机器能访问 MCP 和模型源？
2. **MCP 接口**：Streamable HTTP/SSE/stdio 中的哪一种、endpoint、协议版本、TLS/代理要求，以及鉴权方式。
3. **MCP 工具契约**：`tools/list` 的结果，或下载、训练、部署、组合、数据处理各工具的名称和 JSON Schema。
4. **模型清单**：模型 ID、来源（Hugging Face/ModelScope/对象存储等）、revision、精度/量化、许可限制、目标保存位置。
5. **训练需求**：任务类型，基座模型，LoRA/全参等方式，超参数，GPU 型号/数量，显存，框架及版本，验收指标。
6. **部署需求**：推理框架（如 vLLM/TGI/Triton）、副本数、GPU、端口/网关、健康检查、回滚策略和目标 SLA。
7. **模型组合语义**：是路由、串联、并行集成、权重合并，还是多模态工作流；输入输出契约和失败策略。
8. **数据集**：内网可见路径/对象存储 URI、图像/视频格式、标注格式、规模、抽样示例、期望输出和隐私/留存要求。

## 推荐

- 一个非生产 MCP 环境和最小测试数据集。
- 任务幂等键、超时/重试规则、异步 job 状态查询与取消接口。
- 日志、指标、追踪系统的接入方式；需要脱敏的字段。
- CI 运行器所在网络、Python 版本、依赖镜像源和容器基础镜像。
- GitHub 分支策略、是否允许推送、目标分支及 CI/密钥配置方式。

拿到工具 Schema 后，优先只调整 `configs/*.toml`；若远端使用异步任务，再为工具结果增加轮询适配器。
